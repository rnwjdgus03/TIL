## 1-4. 질문 응답 (Question Answering, QA)

문서 내에서 질문에 대한 정답을 추론하는 task입니다.

QA는 크게 두가지로 나눠집니다.

### 추출형 QA (Extractive QA)

추출형 QA는 정답이 주어진 문맥에서 직접 추출되는 방식의 작업입니다. 이는 문서 내에 명시된 정보를 기반으로 정답을 찾아내는 유형으로, 질문의 답이 항상 문맥 내에 존재하며, 모델이 해당 답을 위치별로 찾아내는 과정입니다.

```python
dataset = datasets.load_dataset('squad', split = "train", streaming=True)

temp = None
for i, example in enumerate(dataset):
    temp = example
    break

print(temp)
```

```python
>> {'id': '5733be284776f41900661182',
   'title': 'University_of_Notre_Dame',
   'context': 'Architecturally, the school has a Catholic character...(중략)',
   'question': 'To whom did the Virgin Mary allegedly appear in 1858 in Lourdes France?'
   'answers': {'text': ['Saint Bernadette Soubirous'],
						   'answer_start': [515]}}
```

데이터의 구조는 데이터셋마다 다르지만 일반적으로 다음 내용을 포함하고 있습니다.

- context: 질문에 대한 정답이 포함된 문서 또는 텍스트.
- question: 사용자가 묻는 질문.
- answers: 주어진 문맥에서 추출된 정답(단어 또는 문장).
- answer_start: 문맥에서 정답이 시작되는 위치.

이와 같은 구조에서 모델은 질문에 대한 정답이 어디에서 시작되고 끝나는지를 예측하게 됩니다.

위 데이터셋을 자세히 살펴보려면 [링크](https://huggingface.co/datasets/rajpurkar/squad)를 참조하세요.

### 생성형 QA (Generative QA)

주어진 문맥에 근거하여 정답을 생성하는 task입니다.

데이터는 다음과 같은 구성을 갖고 있습니다.

- id
    
    구분자입니다.
    
    ```python
    import datasets
    from IPython.core.display import display, HTML
    
    dataset = datasets.load_dataset('natural_questions', split = "train", streaming=True)
    
    temp = None
    for i, example in enumerate(dataset):
        temp = example
        break
    
    display(HTML(temp["document"]["html"]))
    ```
    
- document
    - html : 본문입니다. 아래서 예시를 보여드리겠습니다.
    - title : 문서의 제목입니다.
    - tokens : html 문서에서 html 문법 부분을 제거한 토큰입니다.
    - url : 데이터 출처 url입니다.
    
    ![image.png](6%EC%9B%9429%EC%9D%BC(NLP)/image.png)
    
- question
    - text
        
        사용자 질문이 들어 있는 항목입니다. 질문은 일반적으로 단일 문장으로 구성되어 있으며, 문맥에 대한 답을 요구합니다. 모델은 이 질문을 기반으로 주어진 문서에서 정답을 찾아야 합니다. 질문은 정답의 유형(짧은 답변 또는 긴 답변)을 예측하는 데 중요한 단서를 제공합니다.
        
    - tokens
        
        질문을 토큰화한 데이터입니다.
        
    
    ```
    {'text': 'when is the last episode of season 8 of the walking dead',
     'tokens': ['when',
      'is',
      'the',
      'last',
      'episode',
      'of',
      'season',
      '8',
      'of',
      'the',
      'walking',
      'dead']}
    ```
    
- long_answer_candidates
    
    긴 답변(Long Answer)은 대체로 문서 내의 특정 단락이나 리스트와 같은 긴 텍스트로 구성됩니다. 모델은 이 후보들 중에서 가장 적합한 긴 답변을 선택하는 과정을 거칩니다.
    
    아래와 같은 구조를 갖습니다.
    
    ```python
    {'start_token': 100, 'end_token': 200, 'top_level': True}
    ```
    
    - start_byte / end_byte : 바이트 기준 답변이 될 수 있는 긴 답변의 시작 지점과 끝 지점입니다.
    - start_token / end_token : 토큰 기준 답변이 될 수 있는 긴 답변의 시작 지점과 끝 지점입니다.
    - top_level : HTML 문서의 트리 구조에서 해당 답변의 위치가 top level 인지를 판별합니다. 아래 예시와 같이 첫번째 두 번째 문장은 각각 div와 ul 한 계층만 감싸져있지만 세번째 문장은 div에 의해 두 계층이 감싸져있습니다.
        
        ```html
        <html>
          <body>
            <div>
              <p>First top-level sentence.</p>
            </div>
            <ul>
              <li>Second top-level sentence.</li>
            </ul>
            <div>
              <div>
                <p>Non top-level sentece.</p>
              </div>
            </div>
          </body>
        </html>
        ```
        
        natural_questions 데이터셋에서는 최상위 레벨에 있는 텍스트가 더 중요한 정보로 간주되고, 모델이 우선적으로 이 부분을 답변 후보로 처리하는 경향이 있습니다.
        
- annotations
    
    실제 정답이 항목입니다. annotatation은 해당 문서에서 정답입니다.
    
    이 항목은 정답을 포함하는 범위와 유형을 지정합니다. 여기에는 긴 답변(long answer)과 짧은 답변(short answer)의 위치 정보가 포함됩니다. 모델이 이 annotatation 정보를 활용하여 정답을 학습하게 됩니다.
    
    yes_no_answer의 경우 해당 질문에 대한 답변이 “예”이면 1, “아니오”면 0, 예/아니오로 답변할 수 없는 질문은 -1로 표기됩니다.
    
    ```python

     'long_answer': [{'candidate_index': 92,

       'end_token': 3538,
       'start_byte': 82798,
       'start_token': 2114}],
     'short_answers': [{'end_byte': [96731],
       'end_token': [3525],
       'start_byte': [96715],
       'start_token': [3521],
       'text': ['March 18, 2018']}],
     'yes_no_answer': [-1]}
    ```

## 1-6. 개체명 인식 (Named Entity Recognition, NER)

텍스트에서 사람, 장소, 조직 등의 고유 명사를 인식하는 작업.

```python
dataset = datasets.load_dataset('conll2003', split = "train", streaming=True)

temp = None
for i, example in enumerate(dataset):
    temp = example
    break

print(temp)
```

```python
{'id': '0',
'tokens': ['EU', 'rejects', 'German', 'call', 'to', 'boycott', 'British', 'lamb', '.'],
'pos_tags': [22, 42, 16, 21, 35, 37, 16, 21, 7],
'chunk_tags': [11, 21, 11, 12, 21, 22, 11, 12, 0],
'ner_tags': [3, 0, 7, 0, 0, 0, 7, 0, 0]
}
```

- tokens
    
    문장을 단어 단위로 토큰화한 데이터입니다.
    
- pos_tags
    
    각 토큰의 품사(Part-of-Speech, POS) 태그를 나타내는 데이터입니다.
    
    샘플 데이터를 예시로 들면 다음과 같습니다.
    
    - `22`: NNP (단수 고유명사)
    - `42`: VBZ (현재형 3인칭 단수 동사)
    - `16`: JJ (형용사)
    - `21`: NN (단수 또는 집합 명사)
    - `35`: TO (to 부정사)
    - `37`: VB (동사 원형)
    - `7`: `.` (문장 부호)
    
    위 내용을 품사로 바꾸면 다음과 같습니다.
    
    ```python
    ['EU', 'rejects', 'German', 'call', 'to', 'boycott', 'British', 'lamb', '.']
    ['NNP', 'VBZ', 'JJ', 'NN', 'TO', 'VB', 'JJ', 'NN', '.']
    ['고유명사', '3인칭 단수 동사', '형용사', '명사', 'to부정사', '동사원형', '형용사', '명사', '문장 부호']
    ```
    
- chunk_tags
    
    청크(Chunk)는 문장을 구문 단위(명사구(NP), 동사구(VP) 등)로 묶은 것입니다. 이는 문장에서 단어들이 어떤 구문 단위를 형성하는지를 나타냅니다.
    
    - 태그셋
        - `11`: B-NP (명사구의 시작)
        - `12`: I-NP (명사구 내부)
        - `21`: B-VP (동사구의 시작)
        - `22`: I-VP (동사구 내부)
        - `0`: O (기타, 구문에 속하지 않는 단어)
    
    샘플을 청크로 변환하면 다음과 같습니다.
    
    ```python
    ['EU', 'rejects', 'German', 'call', 'to', 'boycott', 'British', 'lamb', '.']
    ['B-NP', 'B-VP', 'B-NP', 'I-NP', 'B-VP', 'I-VP', 'B-NP', 'I-NP', 'O']
    ['명사구', '동사구', '명사구-명사구', '동사구-동사구', '명사구-명사구', '기타']
    ```
    
- ner_tags(Named Entity Recognition, 개체명 인식)
    
    각 토큰에 대해 개체명 인식(NER)을 적용한 결과로, 문장 내에서 특정한 고유 명사(Entity)가 무엇인지 인식하는 역할을 합니다. 예를 들어, 인물(Person), 조직(Organization), 장소(Location) 등의 태그가 부여됩니다. NER 태그는 chuck와 유사하게 해당 단어가 개체명인지를 나타내며, B-XXX는 해당 개체명의 시작, I-XXX는 개체명의 내부를 의미합니다. O는 개체명이 아님을 의미합니다.
    
    - 태그셋(인덱스):
        - `3`: B-ORG (조직명 시작)
        - `0`: O (개체명 X)
        - `7`: B-MISC (기타 고유명 시작, 예: 'German', 'British')
    
    샘플에 태그를 달아보겠습니다.
    
    ```python
    ['EU', 'rejects', 'German', 'call', 'to', 'boycott', 'British', 'lamb', '.']
    ['B-ORG', 'O', 'B-MISC', 'O', 'O', 'O', 'B-MISC', 'O', 'O']
    ```
    
    EU는 조직(ORG)으로, German과 British는 기타 고유명(MISC)으로 분류하고 있습니다.
    

위 데이터셋을 자세히 살펴보려면 [링크](https://huggingface.co/datasets/eriktks/conll2003)를 참조하세요.

## 1-7. 텍스트 유사도 (Textual Similarity)

두 텍스트 간의 의미적 유사도를 평가하는 작업입니다.

```python

```

"원숭이 엉덩이는"

# 3. 출력층의 이해

RNN의 경우 내부 동작을 살펴보면 다음과 같습니다.

위에 언급했듯 텍스트부터 텍스트 유사도까지 다양한 출력층이 있으며 이에 따라 출력층의 형태와 사용되는 레이어가 다릅니다. 각 모델과 task마다 다르지만 아래 사항에 대해 이해하고 있으면 베이스라인을 짜는데 큰 무리가 없습니다.

- 어떤 형태의 출력이 필요한지 이해한다
- 각 출력 값이 담고 있는 의미와 필요한 레이어를 이해한다

예를 들어 여러분이 다음에 나올 단어를 예측하고 싶다면 단어사전의 인덱스 숫자가 필요합니다. 그러나 이는 필요한 출력의 형태를 온전히 이해한 것이 아닙니다. 모델은 값을 추론할 수도 있지만 우리는 값이 필요한 것이 아니라 어떤 단어(class)가 와야하는지가 필요하기 때문입니다. 때문에 출력값은 127 같은 숫자가 아닌 [0, 0, 0, 1, 0…] 과 같은 단어 사전 길이만큼의 벡터가 되어야합니다.

각각의 출력 값의 의미는 다음과 같아야합니다.

I 다음에 나올 단어가

- apple일 확률 : 0.1
- like일 확률 : 0.4
- an일 확률 : 0.1
- pie일 확률 : 0.2
- .일 확률 : 0.1

위와 같은 의미를 가진 벡터가 되어야합니다. 이는 모든 데이터들이 개별적으로 계산되는 것이 아니기 때문에 최종 출력층이 softmax을 사용해야합니다.

```python
output_layer = nn.Softmax(dim=<단어 사전의 크기>)
```

문장에 포함된 내용이 긍정인지 부정인지 판별하려면 어떻게 해야할까요?

- 긍정일 확률 : 0.1
- 부정일 확률 : 0.9

위와 같은 의미를 가져서 다음과 같이 진행할 수도 있을 것입니다.

```python
output_layer = nn.Softmax(dim=2)
```

다만 이 경우 긍정을 1, 부정을 0으로 생각하여 0~1 사이의 값을 예측하는 task로 이해할 수도 있습니다. 이 경우 다음과 같이 최종 출력층을 sigmoid로 사용할 수 있습니다.

```python
output_layer = nn.Sigmoid()
```

나이, 가격과 같은 값을 예측해야하는 경우 다음과 같이 사용할 수 있습니다.

```python
output_layer = nn.Linear(in_features=hidden_size, out_features=1)
```

벡터를 예측해야하는 경우도 유사하게 다음과 같이 사용할 수 있습니다.

```python
output_layer = nn.Linear(in_features=hidden_size, out_features=<벡터의 길이>)
```

# 4. 인공지능 학습 프로세스

인공지능 학습 프로세스는 일반적으로 다음과 같은 수순으로 진행됩니다.

1. 프로젝트 목표 설정
    
    전체 프로젝트의 목표가 무엇인지, 이를 위해 어떤 데이터가 필요한지 탐색하고 데이터 수집을 기획합니다. 한 번 데이터를 수집한 후 데이터 수집 항목 변경하기 어렵기 때문에 어떤 정보를 어떻게 수집할 것인지 이 단계에서 설계가 끝나야합니다.
    
2. 데이터 수집
    
    모델을 학습시키기 위한 데이터를 수집하는 단계입니다. 이 단계에서 데이터는 목표에 적합한 다양한 출처에서 수집될 수 있으며, 데이터의 양과 품질이 매우 중요합니다. 데이터가 부족하거나 품질이 낮다면 모델 성능에 직접적인 영향을 미칠 수 있기 때문에 충분한 데이터를 확보하는 것이 핵심입니다. 또한, 수집된 데이터가 편향되거나 부정확하지 않도록 주의해야 합니다.
    
3. 데이터 분석
    
    수집된 데이터를 탐색하고, 데이터의 특성과 분포를 분석하는 단계입니다. 이 과정에서 데이터가 학습에 적합한지, 결측값이나 이상치가 있는지 확인합니다. 다양한 시각화 기법과 통계 분석을 활용해 데이터의 패턴을 파악하며, 목표 달성을 위해 추가적으로 필요한 데이터가 있는지 검토합니다. 데이터의 특성을 명확히 이해해야 이후 전처리와 모델링 단계에서 오류를 줄일 수 있습니다.
    
4. 데이터 라벨링
지도학습의 경우 데이터에 대한 레이블이 필요합니다. 데이터에 레이블이 없는 경우 Ground Truth의 품질은 모델의 성능과 직결되기 때문에 라벨링 작업은 매우 중요한 추가 단계가 됩니다. 이미지 분류 문제에서는 사람이 이미지에 대해 직접 라벨을 지정하거나, 텍스트 분류에서는 텍스트가 어떤 카테고리에 속하는지 태깅하는 작업을 수행합니다.
5. 데이터 전처리
    
    모델이 효율적으로 학습할 수 있도록 데이터를 정리하고 변환하는 과정입니다. 불필요한 정보, 노이즈 등이 이 단계에서 제거되며 반대로 이 단계에서 기존의 데이터에서 추출한 특징이 새로운 데이터로 생성됩니다. 또한, 데이터를 학습용과 평가용으로 나누는 작업도 포함됩니다. 이 단계가 제대로 수행되지 않으면 모델 성능이 저하될 수 있으므로, 데이터를 깨끗하고 일관성 있게 처리하는 것이 중요합니다.
    
6. 모델 빌드
    
    학습할 모델을 설계하고 구현하는 단계입니다. 이 단계에서는 프로젝트 목표에 맞는 모델 아키텍처를 선택하고, 적절한 하이퍼파라미터를 설정합니다. 모델은 문제의 복잡도와 데이터 특성에 맞게 설계되어야 하며, 단순한 선형 모델부터 복잡한 신경망 모델까지 다양하게 고려할 수 있습니다. 이 단계에서의 선택은 이후 학습 성능과 평가 결과에 큰 영향을 미칩니다.
    
7. 모델 학습
    
    설계된 모델에 데이터를 입력하여 학습시키는 단계입니다. 모델이 주어진 데이터를 바탕으로 패턴을 학습하고, 예측할 수 있도록 가중치를 최적화합니다. 이 과정에서 손실 함수와 최적화 알고리즘이 사용되며, 학습 과정에서 모델의 성능을 평가하고 필요한 경우 하이퍼파라미터를 조정하는 것이 중요합니다. 과적합을 방지하기 위해 교차 검증과 같은 기법을 사용할 수 있습니다.
    
8. 모델 평가
    
    학습된 모델이 얼마나 잘 동작하는지 평가하는 단계입니다. 모델이 학습하지 않은 평가용 데이터를 사용해 성능을 측정하고, 정확도, 정밀도, 재현율, F1 점수와 같은 다양한 지표로 모델을 평가합니다. 이 단계에서 모델이 과적합이나 과소적합을 일으키지 않았는지 확인하며, 성능이 목표에 부합하지 않으면 모델을 다시 학습시키거나 데이터를 보강할 필요가 있습니다.
    

하지만 NLP, 그중에서도 텍스트 생성의 경우 생성된 텍스트가 정확한지에 대한 지표 이외에도 생성된 문장 자체가 자연스러운지 역시 평가 대상에 포함되어야합니다. 아직까지 생성된 문장이 얼마나 자연스러운지, 또 전체 문맥에 잘 들어맞는지를 평가하는 알고리즘이 확정되지 않았기 때문에 사람이 직접 개입해야할 수도 있습니다.

1. 모델 배포
    
    학습되고 평가된 모델을 실제 환경에 적용하는 단계입니다. 모델은 API나 애플리케이션에 통합되어 배포되며, 실시간으로 데이터를 입력받고 예측을 수행하게 됩니다. 배포된 모델은 지속적인 모니터링을 통해 성능이 유지되는지 확인하며, 새로운 데이터가 들어오면 모델을 재학습시킬 수도 있습니다. 이 단계에서는 모델의 확장성, 응답 속도, 안정성 등을 고려해 최적의 배포 환경을 설계하는 것이 중요합니다.
    

위 단계 중 5~8 단계에 대하여 코드로 구현해보겠습니다.

## 4-1. 데이터 수집 ~ 데이터 전처리

데이터는 y와 상관관계가 있는 $x_{1}$, $x_{2}$, $x_{3}$, y와 무관한 $x_{4}$, $x_{5}$로 이루어져있습니다.

y에는 $x_{4}$, $x_{5}$이외에도 일부 노이즈를 추가했습니다.

따라서 y값은 $y = 3x_{1}+2x_{2}-x_{3}$에 일부 노이즈가 포함된 값이며 이 데이터를 학습하여 유사한 모델을 추론하는 것이 프로젝트 목표입니다.

```python
import torch
import numpy as np
import matplotlib.pyplot as plt

def generate_data(num_samples):
    np.random.seed(42)

    x1 = np.random.uniform(0, 10, num_samples)
    x2 = x1 + np.random.normal(0, 1, num_samples)
    x3 = 2 * x1 + 3 * x2 + np.random.normal(0, 1, num_samples)
    x4 = np.random.uniform(0, 10, num_samples)
    x5 = np.random.uniform(0, 10, num_samples)
    
    y = 3 * x1 + 2 * x2 - x3 + np.random.normal(0, 0.5, num_samples)
    
    X = np.stack([x1, x2, x3, x4, x5], axis=1)
    return torch.tensor(X, dtype=torch.float32), torch.tensor(y, dtype=torch.float32).unsqueeze(1)

X, y = generate_data(1000)

plt.figure(figsize=(12, 4))

plt.legend()
plt.subplot(1, 3, 2)

plt.legend()
plt.subplot(1, 3, 3)
plt.scatter(X[:, 2], y, label='x3 vs y', alpha=0.5)
plt.legend()
plt.show()
```

## 4-3. 모델 학습

학습 루프는 다음 수순을 따릅니다.

1. 배치 단위로 모델 추론
2. 손실값 계산
3. 역전파
역전파에는 일반적으로 파라미터 업데이트까지 포함해서 말하는 경우가 많지만 파이토치에서는 각 파라미터의 기울기를 구하는 역전파와 옵티마이저를 통한 파라미터 업데이트가 분리되어 있습니다.
4. 파라미터 업데이트
5. 모든 배치에 대하여 학습할때까지 1~4를 반복 및 데이터 전체에 대한 손실값 기록
6. 1회 학습이 끝나면 Validation으로 모델 평가
7. 지정한 에포크 만큼 1~6까지의 과정을 반복

```python
def train_model(num_epochs=100):
    model.train()
    history = []
    val_history = []

    for epoch in range(num_epochs): # 7
        total_loss = 0
        model.train()

        for inputs, labels in train_loader: # 5
            optimizer.zero_grad()
            outputs = model(inputs) # 1
            loss = criterion(outputs, labels) # 2
            loss.backward() # 3
            optimizer.step() # 4
            total_loss += loss.item() # 5

        history.append(total_loss / len(train_loader)) 

        print(f"Epoch [{epoch+1}/{num_epochs}], Train Loss: {total_loss/len(train_loader):.4f}", end = " ")

        model.eval() # 6
        val_loss = 0
        with torch.no_grad():
            for inputs, labels in val_loader:
                outputs = model(inputs)
                loss = criterion(outputs, labels)
                val_loss += loss.item()
        
        val_history.append(val_loss / len(val_loader))

        print(f"Validation Loss: {val_loss/len(val_loader):.4f}")
    return history, val_history

history, val_history = train_model(num_epochs=100)

plt.plot(range(1, len(history)+1), history, label='Train Loss')
plt.plot(range(1, len(history)+1), val_history, label='Validation Loss')
plt.xlabel('Epochs')
plt.ylabel('Loss')
plt.title('Loss over epochs')
plt.legend()
plt.show()
```

Train/Validation Loss를 그래프로 그리는 것은 파이토치에서 일반적인 방법은 아니지만(주로 텐서플로우에서 많이 사용됨) 학습 진행 상태, 특히 과적합에 대하여 직관적으로 이해할 수 있기 때문에 추천드립니다.

# 5. Pretrained Model

Pretrained Model이란 이미 학습된 모델을 활용하여 새로운 작업에 적용하는 방법을 말하며 일반적으로는 대규모 데이터셋을 통해 학습된 모델을 의미합니다. Pretrained Model을 사용할 경우 다음과 같은 장점이 있습니다.

- 시간과 자원의 절약
    
    모델을 처음부터 학습하는 데는 엄청난 데이터, 시간, 그리고 컴퓨팅 자원이 필요합니다. 하지만 이미 학습된 모델을 사용하면 훨씬 적은 자원으로 높은 성능을 얻을 수 있습니다.
    
- 일반화 능력
    
    대규모 데이터셋에서 학습된 모델은 특정 문제에 대한 성능만이 아니라, 일반적으로 다양한 문제에도 잘 적응할 수 있습니다. 이는 사전 학습된 모델을 사용하는 주요 장점 중 하나입니다.
    
- 전이 학습(Transfer Learning)
    
    Pretrained Model을 기반으로 새로운 작업에 맞게 모델을 미세 조정(Fine-tuning)할 수 있습니다. 이를 통해 더 적은 데이터로도 좋은 성능을 얻을 수 있습니다.
    

우리가 수집하는 데이터는 대부분 특정 분야에 대하여 한정되기 쉽기 때문에 이러한 데이터만 학습한 모델은 유사한 분야, 유사한 데이터에 대해서는 기대한 성능을 발휘할 가능성이 높지만 분야가 달라지거나 데이터의 형식 등이 다를 경우 성능을 발휘하기 어렵습니다.

Pretrained Model은 다양한 분야의 대규모 데이터를 학습했기 때문에 특정한 범위 내에서는 위의 경우보다 조금 더 향상된 일반화 성능을 기대할 수 있습니다. 이를 통해 특정 문제에 대한 성능 뿐만 아니라 다양한 문제에 대해서도 잘 동작할 수 있습니다. 하지만 다음과 같은 사항을 고려해야합니다.

- 일반적으로 Pretrained Model은 일반화 성능을 위해 다양한 분야의 데이터를 학습합니다. 이는 모델이 범용성을 가질 수 있지만 동시에 특정 분야에 대하여 잘못된 추론을 할 수 있습니다. 예를 들어 trasfomer라는 단어를 인공지능의 모델인 Transformer로 이해할 수도 있지만 변압기, 혹은 영화 제목으로 이해할 수도 있습니다.
- 다양한 분야의 데이터를 학습하더라도 해당 데이터에 내가 필요한 분야의 데이터가 포함되어있지 않을 수 있습니다. 예를 들어 Pretrained Model이 학습한 데이터가 일반적인 문서, 대화문 등을 학습하더라도 한정된 전문 분야의 데이터에 대해선 학습하지 못하였을 가능성이 있습니다. 때문에 이런 경우 일반화 능력을 통해 일정 수준까지는 동작하더라도 한계에 봉착하게 됩니다.
- Pretrained Model은 다양한 분야의 데이터, 그리고 다양한 task를 통해 학습합니다. 하지만 모든 task에 대하여 수행하는 것이 아닐 뿐더러 수행해야할 task와 결과 값이 상이한 경우가 많습니다.
예를 들어 모델이 classification에 대하여 수행할 수 있지만 어떤 class를 추론해내야하는지 다를 수 있습니다. 모델의 경우 10가지의 class에 대하여 구분하지만 내가 필요한 class가 4가지일 경우 원하는 것과 다른 결과를 추론하게 됩니다.

위와 같은 이유로 인해 Pretrained Model을 사용하더라도 해당 모델의 기본적인 학습된 지식을 활용하면서도 새로운 작업에 맞게 모델을 조정하는 Transfer Learning, 그중에서도 Fine Tunning을 자주 사용합니다.

CNN와 RNN 두가지 모델에 대하여 모델의 각 부분이 어떤 내용을 학습하는지 예시를 들도록 하겠습니다.

## 5-1. Feature Extractor

![VGG16[[링크]](https://en.wikipedia.org/wiki/File:VGG_neural_network.png)](6%EC%9B%9429%EC%9D%BC(NLP)/VGG.png)

VGG16[[링크]](https://en.wikipedia.org/wiki/File:VGG_neural_network.png)

위 모델은 VGG16의 구조를 도식화한 것입니다.

VGG16은 ILSVRC-2012(이미지넷 대회 데이터셋)에서 학습되었습니다. 이 데이터셋은 약 120만 장의 이미지와 1000개 클래스로 구성되어 있으며, 일상 생활에서 접할 수 있는 다양한 객체를 포함하고 있습니다. 이를 통해 VGG16은 일반적인 이미지에서 객체를 잘 분류할 수 있도록 학습되었습니다.

각각의 도형은 다음 Layer를 통과한 결과입니다.

- **Conv Layer** : 입력 이미지에서 특징을 추출하는 역할을 합니다.
- **Pooling Layer** : 특징 맵을 축소하여 계산 비용을 줄이고, 중요한 특징을 강조합니다.
- **FC Layer** : 모든 뉴런이 연결되어 전체 이미지를 학습하고 분류합니다.
- **Softmax Layer** : 확률 분포를 계산하여 최종 분류를 수행합니다.

Feature Extractor와 Classifier는 각각 다음과 같은 내용을 학습하게 됩니다.

### Feature Extractor

입력 이미지를 작은 필터(커널)로 스캔하며, 픽셀 간의 관계를 학습합니다. 초기 레이어에서는 주로 저수준 특징을 학습하게 되며, 이는 이미지에서 선, 모서리, 색상과 같은 기초적인 패턴입니다. 이후 레이어로 갈수록 이미지의 고수준 특징(예: 개나 고양이의 특정 형태, 눈, 귀 등의 형태)을 학습합니다.

- 초기 Conv Layer : 주로 이미지의 기본적인 형태(선, 에지, 텍스처)를 학습합니다.
- 중간 Conv Layer : 이미지 내 구조적인 패턴(예: 동물의 다리, 얼굴 윤곽 등)을 학습합니다.
- 후반 Conv Layer : 전체적인 형태(예: 고양이의 전체 얼굴, 강아지의 전체 몸 형태)를 학습합니다.

### Classifier

Classifier는 Feature Extractor가 추출한 특징을 바탕으로 최종적으로 이미지가 어떤 클래스에 속하는지 결정하는 역할을 합니다. 주로 Fully Connected Layer로 구성되며, 다음 단계를 수행합니다:

- FC Layer: Conv Layer와 Pooling Layer에서 추출된 특징 맵을 1차원 벡터로 펼쳐, 각각의 뉴런이 모든 입력에 연결된 상태로 학습을 진행합니다. FC Layer는 이 벡터를 사용해 각 클래스에 대한 확률 점수를 계산하고, 학습 데이터를 통해 그 점수를 학습합니다.
    - 예를 들어, 강아지와 고양이 분류 문제에서는 FC Layer가 강아지 또는 고양이에 속할 가능성을 계산하는데, 해당 특징들이 특정 클래스와 어떻게 관련이 있는지를 학습합니다.
- Softmax Layer: 마지막 FC Layer의 출력값을 확률로 변환하여, 이미지가 각 클래스에 속할 확률을 계산합니다. 이 확률을 통해 가장 높은 확률을 가진 클래스가 예측 값으로 결정됩니다.

위와 같이 학습된 VGG16을 가지고 와서 새로운 데이터에 적용 시킬 경우 다음과 같은 문제가 있을 수 있습니다.

- Classifier
    
    Classifier가 이미지넷의 데이터에 맞춰 1000개의 클래스를 구분하도록 학습하였기 때문에 기존과 다른 class를 분류하려고 할 경우 추가적으로 학습하거나 혹은 새로운 classifier로 변경해야합니다.
    
- Feature Extractor
    
    위의 Pretrained VGG16은 일반적인 객체에 대하여 광범위하게 학습하였기에 강아지와 고양이를 분류하는 작업에는 잘 동작합니다. 하지만 데이터셋에 포함되지 않은 객체를 인식하기 위해선 추가적인 학습이 필요합니다. 단, 기존 데이터들과 얼마나 큰 차이가 있는지에 따라 어디까지 추가학습이 필요한가는 달라지게 됩니다.
    

## 5-2. RNN 및 언어 모델

RNN 모델의 경우 다음과 같습니다.

![image.png](6%EC%9B%9429%EC%9D%BC(NLP)/image%209.png)

각 레이어가 학습하는 내용은 다음과 같습니다.

### Embedding Layer(입력층)

Embedding Layer는 단어를 고차원 임베딩 벡터로 변환하는 역할을 합니다. 텍스트 데이터는 단어사전을 거쳐 고유 인덱스로 표현되는데, 이러한 정수를 Embedding Matrix와 연산하여 Dense Vector(밀집 벡터)로 변환합니다. 이 벡터는 해당 단어가 어떤 의미를 가지는지, 단어 간의 유사도를 반영할 수 있습니다.

이를 통해 Embedding Layer는 각 단어의 의미를 벡터 공간에서 학습하여 단어 간의 의미적 유사성을 학습합니다. 예를 들어, '강아지'와 '고양이'가 비슷한 맥락에서 자주 등장하면, 이 두 단어의 임베딩 벡터는 유사하게 학습됩니다.

### RNN (은닉층)

RNN은 입력된 임베딩 벡터와 이전 시점의 hidden state를 결합하여, 시퀀스 내에서 순차적인 정보를 처리합니다. 각 시점의 hidden state는 이전 시점에서 학습된 정보를 유지하면서, 새로운 입력 단어의 정보를 반영합니다.

위 과정을 통해 RNN은 문맥 정보와 순차적 의존성을 학습합니다. 특히 이전 단어들이 다음 단어의 예측에 어떻게 영향을 미치는지 학습하며, 문맥의 흐름을 유지하고 문장 전체에서 단어들이 어떤 관계를 맺고 있는지 학습하여, 다음 단어를 예측할 수 있는 문맥 의존성을 구축합니다.

### Fully Connected Layer(출력층) + Softmax

RNN의 hidden state를 FC Layer를 통해 출력 차원(단어 사전 크기)으로 변환합니다. Hidden state는 크기가 제한된 벡터이기 때문에, 이를 사용하여 단어 사전에서 어떤 단어를 선택할지 결정하기 위한 변환 작업이 필요합니다. FC Layer는 hidden state를 단어 사전 크기만큼의 출력으로 변환하는 작업을 하며, 단어별로 가중치를 학습합니다. 이는 주어진 문맥에서 특정 단어가 나올 확률을 계산하기 위한 과정입니다.

Softmax는 최종적으로 각 단어의 확률을 계산하여, 그 중 가장 높은 확률을 가진 단어가 다음에 생성될 단어로 선택됩니다.

### Pretrained Model

RNN과 같은 언어 모델 역시 대규모 데이터셋을 통해 학습된 Pretrained Model을 활용할 수 있으며 CNN의 경우와 마찬가지로 사용할 분야, 갖고 있는 데이터셋 등에 따라 어떤 부분을 fine tunning할지 혹은 새로 모델을 만들어 학습시킬지 정해야합니다.

단, 언어 모델에서 Pretrained Model을 사용할 경우 단어를 토큰화할 tokenizer와 단어 사전을 함께 가져와야합니다.

## 5-3. Fine Tunning

Fine-tuning은 사전 학습된 모델을 사용하여, 새로운 작업이나 더 작은 데이터셋에 맞추어 모델을 재학습하는 기법입니다. 이 방법은 사전 학습된 가중치를 이용하여 더 빠르고 효율적으로 학습할 수 있도록 도와주며, 특히 적은 양의 데이터로도 높은 성능을 얻을 수 있습니다.

Fine-tuning의 과정은 다음과 같습니다.

1. 사전 학습된 모델 불러오기
    
    대규모 데이터셋에서 학습된 모델(예: ImageNet에서 학습된 VGG16 등)을 불러옵니다.
    
2. 모델의 일부 레이어 고정
    
    학습이 필요하지 않은 레이어, 특히 초기 레이어들은 일반적인 패턴(예: 이미지의 기본 특징, 텍스트에서의 일반적 문맥)을 이미 잘 학습했기 때문에, 새로운 작업에 맞추기 위해서는 추가로 학습할 필요가 없는 경우가 많습니다.
    
    이런 경우 초기 레이어는 사전 학습된 가중치를 고정하고 후반부 레이어만 학습 가능하게 설정합니다.
    
3. 새로운 작업에 맞춘 학습
    
    기존의 레이어를 대체한 레이어나 고정하지 않은 레이어만 새로운 작업에 맞추어 다시 학습(Fine-tuning)합니다. 주로 후반부의 FC Layer나 Classifier를 학습하는 경우가 많습니다.
    

Fine-tunning은 갖고 있는 데이터셋과 task, Pretrained Model이 학습한 데이터셋과 task에 따라서 다음과 같이 학습할 부분과 정도가 달라집니다.

### 데이터셋과 task가 유사

이런 경우 Pretrained 모델을 그대로 사용하거나 다른 부분의 가중치를 동결시켜두고 최종 출력층 부분만을 조금 학습시킵니다.

예를 들어 고양이와 강아지 분류 문제를 해결하기 위해 ImageNet 데이터셋으로 학습된 VGG16 모델을 사용한다고 가정하면 Classifier의 마지막 Fully Connected Layer만 고양이와 강아지에 맞게 다시 학습시켜도 충분한 성능을 발휘할 수 있습니다. 이 경우, Conv Layer에서 추출된 특징은 여전히 유효하기 때문에 초기 레이어는 고정하고 Classifier의 일부만 학습시킵니다.

### 데이터셋은 유사, task는 상이

이 경우 FC layer나 classifier같은 출력층 부분을 재설계하고 학습시킵니다. 데이터셋이 유사하기 때문에 입력층과 은닉층의 가중치는 동결시키고 출력층을 학습시킨 이후 필요에 따라 추가적으로 학습시킵니다.

예를 들어 Pretrained된 번역기 모델을 분류기로 활용할 경우 거의 유사한 데이터를 활용하기 때문에 출력층 부분만 Classifier로 변경하고 이 부분만 다시 학습 시킬 수 있습니다.

### 데이터셋이 상이

데이터셋이 상이한 경우에도 Pretrained Model은 일반적인 이미지의 기본 특징이나 텍스트의 문맥 정보를 잘 학습되어있기 때문에 이를 바탕으로 학습시킬 경우 갖고 있는 데이터셋으로만 학습시키는 경우보다 일반화 성능이 높을 수 있습니다.

다만 출력층을 새로 바꾼 다음 학습 시킬 경우 처음부터 모든 계층을 학습시키면 출력층이 갖고 있는 오류가 이미 학습된 내용에 악영향을 미칠 수 있습니다. 때문에 새로 바꾼 계층만 먼저 학습시키고 나서 전체를 학습시키는 등의 추가적인 기법이 필요합니다.

### Few-shot과 Fine-tunning의 차이

Fine-tuning과 더불어 언급되는 방식인 Few-shot Learning은 둘 다 사전 학습된 모델을 활용하는 기법이지만, 적용 방식과 사용되는 데이터 양에서 차이가 있습니다.

| 구분 | Fine-tunning | Few-shot Learning |
| --- | --- | --- |
| 데이터 | 비교적 적은 양일 뿐 데이터의 특징을 학습할 수 있을만큼의 충분한 데이터셋이 필요합니다. | 몇 개의 샘플만을 통해 학습합니다. |
| Pretrained Model | Pretrained Model의 일부 레이어, 혹은 전체 모델을 학습합니다. | Pretrained Model을 거의 그대로 사용합니다. |
| 학습 방식 | 기준 가중치를 조정하며 학습합니다. | Meta-learning 기법을 통해 모델이 다양한 작업에 대해 빠르게 적응할 수 있도록 학습합니다. 학습 자체를 학습하는 과정이 포함되어 있습니다. |

이전에는 주로 대규모 이미지 데이터셋을 통해 학습된 모델(CNN 기반 모델 등)이 Few-shot Learning에 활용되었지만, 최근에는 대규모 언어 모델(LLM, Large Language Models) 역시 Few-shot Learning을 통해 새로운 작업을 수행할 수 있는 것으로 알려져 있습니다. LLM은 대규모 텍스트 데이터에서 학습된 지식을 바탕으로, 몇 가지 샘플만으로도 다양한 작업에 빠르게 적응하는 능력을 가지고 있습니다.

```python
def train_model(model, train_loader, val_loader, optimizer, criterion, device, epochs=5):
    model.train()
    history = [[], []]
    val_history = [[], []]

    for epoch in range(epochs):
        running_loss = 0.0
        correct = 0
        total = 0
        
        for inputs, labels in train_loader:
            inputs, labels = inputs.to(device), labels.to(device)

            optimizer.zero_grad()

            outputs = model(inputs)

            loss = criterion(outputs, labels)

            _, predicted = torch.max(outputs, 1)

            loss.backward()
            optimizer.step()

            running_loss += loss.item()
            total += labels.size(0)
            correct += (predicted == labels).sum().item()

        epoch_loss = running_loss / len(train_loader)
        epoch_acc = 100 * correct / total
        print(f"Epoch [{epoch+1}/{epochs}], Train_loss: {epoch_loss:.4f}, Train_accuracy: {epoch_acc:.2f}%", end = " ")
        history[0].append(epoch_loss)
        history[1].append(epoch_acc)

        val_loss, val_acc = evaluate_model(model, val_loader, criterion, device)
        print(f"Val_loss: {val_loss:.4f}, Val_accuracy: {val_acc:.2f}%")
        val_history[0].append(val_loss)
        val_history[1].append(val_acc)

    return history, val_history
```

```python
def evaluate_model(model, data_loader, criterion, device):
    model.eval()
    total_loss = 0.0
    correct = 0
    total = 0

    with torch.no_grad():
        for inputs, labels in data_loader:
            inputs, labels = inputs.to(device), labels.to(device)

            outputs = model(inputs)

            loss = criterion(outputs, labels)

            _, predicted = torch.max(outputs, 1)

            total_loss += loss.item()
            total += labels.size(0)
            correct += (predicted == labels).sum().item()

    avg_loss = total_loss / len(val_loader)
    avg_acc = 100 * correct / total

    return avg_loss, avg_acc
```

## 6-2. Pretrained Model 사용

Pretrian Model을 사용하는 과정은 다음과 같습니다.

1. Pretrained된 모델을 불러옵니다.
2. 모델의 구조를 필요에 따라 수정합니다.
3. 가중치를 동결시킬 레이어를 선택합니다.
4. Fine-tunning합니다.

여기에서는 가중치를 동결시키고 새로 추가한 레이어만 먼저 학습을 시킨 후 필요한만큼 동결을 해지하여 전체적으로 Fine-tunning하는 방법을 사용하겠습니다.

위에서 사용한 데이터, 학습 및 평가 함수는 그대로 사용합니다.

우선 Pretrained Model을 가져오겠습니다.

```python
model = models.vgg16(pretrained=True).to(device)
model.classifier[6] = nn.Linear(4096, 2).to(device)

criterion = nn.CrossEntropyLoss()
optimizer = optim.Adam(model.classifier.parameters(), lr=0.001)
```

모든 레이어를 동결시키고 classifier의 가장 마지막 레이어만 학습되도록 하겠습니다.

```python
for param in model.parameters():
    param.requires_grad = False

for param in model.classifier[6].parameters():
    param.requires_grad = True
```
